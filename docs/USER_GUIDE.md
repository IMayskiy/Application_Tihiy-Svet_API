# Установка и работа

## Подготовка

1. Установите Node.js 24 или новее с npm и получите файлы репозитория через `git clone` либо Download ZIP → распаковка.
2. Откройте терминал в папке с `package.json`.
3. Выполните `npm ci`. Команда устанавливает зависимости из `package-lock.json`.
4. Создайте локальный `.env` из `.env.example`. В PowerShell: `Copy-Item .env.example .env`. Если `.env` уже есть, сохраните существующий файл и не копируйте поверх него.
5. Локально заполните `OPENAI_API_KEY` и `OPENAI_MODEL`. Никому не передавайте содержимое `.env`.

Модель должна поддерживать Responses API, строгую схему, вызов функций и параметры, используемые проектом, включая `reasoning.effort: 'none'`. Код использует `gpt-6-luna` как запасное значение, но его доступность не проверена. Укажите подходящий ID в своём аккаунте; при ошибке совместимости потребуется проверить настройки запросов.

## Запуск и остановка

```powershell
npm start
```

Откройте [http://127.0.0.1:3030/](http://127.0.0.1:3030/). Адрес и порт фиксированы. Сервер работает в терминале до нажатия **Ctrl+C**. Для разработки используйте `npm run dev`.

Если npm недоступен, но в вашей локальной папке уже есть копия `.tools/npm`, можно использовать `node .tools/npm/bin/npm-cli.js ci` и `node .tools/npm/bin/npm-cli.js start`. Эта локальная служебная копия не поставляется в репозитории.

Надпись «Настроено» означает только, что сервер смог подготовить клиент API. Она не проверяет действительность ключа, баланс или доступность модели.

## Работа с обращением

1. Вставьте текст до 4 000 символов либо нажмите «Загрузить обращение» и выберите `.txt` из `examples/`.
2. При необходимости нажмите «Получить текстовый ответ» для сводки и вопросов.
3. Нажмите «Собрать карточку», сверьте её с исходным сообщением. Раздел «Как получен результат» показывает исходный JSON модели.
4. Нажмите «Проверить каталог». Сверьте цену, остаток, расчётную стоимость и неразрешённые вопросы. В подробностях можно увидеть имя и аргументы функции каталога.
5. Нажмите «Сохранить черновик». В окне проверки прочитайте все разделы. «Отмена» закрывает окно без записи; «Подтверждаю сохранение» запускает сохранение.
6. Проверьте сообщение о сохранении и запись в разделе «Сохранённые обращения». Черновик с вопросами допустим, если данные корректны и менеджер подтвердил запись.

Изменение исходного текста делает старые результаты неактуальными. Для продолжения соберите карточку заново и повторите проверку каталога.

## Если ответ о сохранении потерян

Нажмите «Повторить проверку сохранения». Эта кнопка проверяет существующую запись, не запускает сохранение или вызов модели заново. Если операция ещё выполняется, проверьте позже. Не создавайте новое намерение сохранения, пока результат предыдущего не выяснен: защита от дублей действует для одного ID операции, а отдельные намерения могут создать отдельные записи.

## Ошибки и восстановление

| Симптом | Что проверить |
| --- | --- |
| Ключ отсутствует или содержит недопустимые символы | Настройки в локальном `.env`; после исправления перезапустите сервер |
| Ошибка авторизации или доступа | Права ключа и доступ к модели в своём аккаунте |
| Недостаточно средств или исчерпана квота | Биллинг и квоту API |
| Ограничение частоты или 50 запросов | Лимиты аккаунта; лимит запуска сбрасывается перезапуском, но не заменяет контроль расходов |
| Модель не найдена или параметры не поддерживаются | ID модели и совместимость её параметров |
| Адрес занят (`EADDRINUSE`) | Уже запущенный экземпляр на порту 3030; не запускайте второй |
| Карточка устарела | Заново соберите карточку и проверьте каталог |

## Хранение и приватность

Черновики находятся в `data/generated/crm.json`, который создаётся приложением. Он не включён в GitHub. Для резервирования локальных данных остановите сервер и скопируйте этот файл в выбранное вами защищённое место. Не редактируйте его во время работы приложения.

Локальный запуск не означает автономную обработку: сообщения и данные, необходимые для функций, передаются в OpenAI. Запросы устанавливают `store:false`; это параметр API, а не обещание полной анонимности или отсутствия хранения во всех системах. Для показа используйте только вымышленные обращения из `examples/`.

## Тесты без реальных вызовов

```powershell
npm test
```

Тестам не нужен `.env`. Они используют отдельные тестовые ответы, локальный HTTP-сервер и временное хранилище в `tests/`. Пользовательская CRM не участвует в проверках.
