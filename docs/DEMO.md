# Сценарий демонстрации заказчику

Цель — показать путь от сообщения до проверяемого черновика и объяснить, какие решения остаются за менеджером. Используйте только контрольные примеры проекта.

## Подготовка

Установите и запустите приложение по [инструкции](USER_GUIDE.md). Перед показом убедитесь, что в списке обращений нет реальных контактов и конфиденциальных данных. Не выводите `.env` или ключ на экран.

Выберите режим показа:

- **Обзор без API:** откройте интерфейс, покажите исходное сообщение, каталог, ожидаемые результаты и отчёт тестов. Не выдавайте контрольные значения за ответ настоящей модели.
- **Живой показ:** пользователь сам запускает запросы кнопками интерфейса со своим доступом к OpenAI. Запросы могут расходовать средства; ошибка API не подменяется готовым ответом.

## Основной сценарий

1. Объясните задачу: «Менеджеру нужно проверить потребность покупателя по каталогу до обещания поставки».
2. Загрузите `examples/01_main.txt`: 12 белых ламп «Луна 01», бюджет 60 000 ₽, пожелание к 20 ноября.
3. Получите текстовый ответ и карточку. Сверьте количество 12, бюджет и срок. Покажите отсутствующие контакт и точный адрес.
4. Проверьте каталог. Ожидаемые контрольные значения: цена 5 900 ₽, остаток 8, сумма 70 800 ₽, превышение 10 800 ₽, нехватка 4. Дата поставки неизвестна.
5. Откройте просмотр черновика. Покажите источники сведений и вопросы. Нажмите «Отмена»: просмотр сам по себе не сохраняет запись.
6. Если показываете сохранение, снова откройте просмотр и сами подтвердите запись. Покажите ID черновика в списке. Это локальная запись, не заказ и не резерв.
7. Измените исходный текст. Покажите, что старые результаты помечены устаревшими и требуют повторной обработки.

Значения выше — ориентир по файлам проекта. Если реальная модель извлекла другие сведения, покажите расхождение и разберите его; не подправляйте результат ради успешного показа.

## Дополнительные примеры

| Файл | Что показать |
| --- | --- |
| `02_no_budget.txt` | Сумма рассчитывается; сравнение с отсутствующим бюджетом недоступно |
| `03_not_found.txt` | Отсутствующий товар не заменяется другим |
| `04_review_ready.txt` | Вымышленные контакт и адрес; срок остаётся неподтверждённым |
| `05_no_permission.txt` | Команда покупателя не даёт разрешение на сохранение |
| `06_invalid_quantity.txt` | Отрицательное количество должно быть отклонено |

Ожидаемые результаты находятся в `examples/expected.json`. Полнота соблюдения инструкций настоящей моделью не доказывается тестовыми ответами.

## Завершение показа

Откройте [архитектуру](ARCHITECTURE.md) и [результаты проверки](VERIFICATION.md). Обсудите отдельно, какие данные и процессы заказчик хотел бы подключить. Не представляйте внешнюю CRM, многопользовательский режим, публикацию или показатели экономии времени как уже реализованные.
