# Демонстрация проекта

Прочитай `README.md`, `docs/PORTFOLIO.md`, `docs/DEMO.md` и текущие `docs/VERIFICATION.md`. Для проверки утверждений используй исходники, `catalog.json` и `examples/expected.json`. Исторический `ACCEPTANCE.md` не заменяет новый прогон проверок.

Объясняй сценарий менеджера: сообщение → карточка → каталог → расчёт и вопросы → просмотр → явное подтверждение → локальный черновик. Покажи контрольный пример с 12 лампами: 70 800 ₽, превышение 10 800 ₽, нехватка 4 шт., неизвестная дата поставки. Эти числа — контрольные значения, не сведения о продажах.

Различай обзор интерфейса без API и живой показ. Не подставляй готовые ответы в пользовательские маршруты ради демонстрации. Настоящие вызовы и подтверждение записи выполняет пользователь. Не запускай их сам, не читай `.env` и не показывай локальные обращения с реальными данными.

При обновлении кейса указывай дату и фактический результат проверки. Не заявляй внедрение, экономию времени, окупаемость, внешнюю CRM, многопользовательский режим или промышленную готовность без подтверждённых источников. Новые возможности обозначай как отдельный возможный объём работ.

Если нужны изображения, используй фактический интерфейс без секретов и персональных данных. Подпиши состояние экрана и способ получения. Реконструкцию или макет нельзя называть скриншотом работающего приложения.

Обновление документов не разрешает публикацию автоматически: публикуй только по прямой задаче пользователя. При разрешённой публикации отправляй явный список файлов без `.env`, `data/generated/`, зависимостей, кэшей, резервных копий и логов. Сохраняй существующие материалы репозитория, не относящиеся к задаче.
